## 2025-11-14 - MQL5 SymbolInfoInteger Compilation Constraint and TickValue Anti-Pattern
**Learning:** `SymbolInfoInteger` requires a `long` variable as the receiving parameter in MQL5. Passing an `int` variable, even for properties logically representing integers (like `Digits`), results in a compilation error due to reference type mismatch. Additionally, caching `TickValue` in long-lived classes for cross-currency pairs is a performance anti-pattern because it changes dynamically with conversion rates; it should be retrieved fresh.
**Action:** Always use `long` type variables when calling `SymbolInfoInteger` for output parameters. Only cache static symbol properties (like `Point` or `Digits`) and fast dynamic properties (like `Ask`/`Bid` updated via `MqlTick`). Retrieve `TickValue` using `SymbolInfoDouble` dynamically to avoid stale conversion rates without penalizing caching objects.
