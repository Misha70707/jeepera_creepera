## 2024-05-14 - Prevent Secret Leakage via Strict Version Control Configurations
**Vulnerability:** The initial `.gitignore` only focused on MPS build artifacts, leaving the repository vulnerable to accidental commits of sensitive data, such as `.env` files, API keys (`*.key`, `*.pem`), logs (`*.log`), and MT5 specific configurations (`*.set`, `*.ex5`).
**Learning:** In early-stage or skeleton projects lacking comprehensive source code, the primary security vector often shifts from application-level vulnerabilities (e.g., XSS, SQLi) to infrastructure-level leaks. Without strict `.gitignore` exclusions, developers are highly prone to accidentally pushing local secrets to the central repository.
**Prevention:** Implement comprehensive `.gitignore` rules at the project's inception to exclude environment variables, secrets, logs, IDE configurations, and domain-specific artifacts (like MT5 `.ex5` and `.set` files). Treat infrastructure hardening as the first layer of defense in depth.
