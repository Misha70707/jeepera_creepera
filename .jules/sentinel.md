## 2024-03-11 - Infrastructure Gap: Missing Strict Hardening for MT5/ML Repositories
**Vulnerability:** The repository lacked basic security hardening at the configuration management level (specifically `.gitignore`), leaving it highly susceptible to accidental commits of hardcoded secrets, logs, environment variables, Python compilation artifacts, IDE settings, and MT5 executables/presets. Because MT5 code often requires integration with external ML services (like Python pipelines) and uses `.ex5` and `.set` files which could embed proprietary logic, leaving this unchecked is a severe operational risk.
**Learning:** In hybrid repositories involving algorithmic trading (MQL5/MT5) and machine learning (Python), it is essential to defensively exclude environment variables and proprietary execution binaries preemptively. The lack of active code doesn't eliminate risk; developers may quickly iterate on local prototypes that inadvertently commit secrets or binaries to version control.
**Prevention:** Implement strict global or repository-level `.gitignore` exclusions during the project initialization phase. Specifically target `.env`, secret keys, `.ex5` binaries, `.set` files, `__pycache__`, and `*.log` files to ensure defense in depth against accidental secret leakage.
